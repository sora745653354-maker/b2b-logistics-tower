# B2B 物流控制塔｜飞书妙搭迁移包

本包是把现有前端交给飞书妙搭继续改造成云端完整应用的迁移起点，不是可直接发布的成品。它不包含订单数据、TMS 原始报表、本机 SQLite 数据库、联系人字段、凭证或 Cookie。

## 导入

1. 在飞书妙搭选择“导入新建应用”，导入本 ZIP。
2. 选择完整应用/带服务端能力的模式，让妙搭把当前单页控制塔迁移到托管数据库和服务端接口。
3. 将下面“迁移要求”作为妙搭的首条开发指令。先在预览态校验，再配置为仅组织内登录用户可访问；确认权限和数据刷新后才发布。

## 迁移要求（复制给妙搭）

请把导入的 B2B 物流控制塔迁移为可在飞书妙搭云端运行的完整应用，并尽可能保留原页面布局、筛选、图表、明细、导出、业务日期和物流规则。先盘点现有页面与接口依赖，列出迁移计划，未经校验不要删除或改写业务口径。

- 访问控制：仅允许已登录且有应用权限的本企业飞书用户访问；禁止公开匿名访问。
- 存储：使用妙搭托管的 PostgreSQL/应用数据库。建立批次、当前 SOO 订单快照、仓库/区域/承运商映射、出库订单匹配、小时提货状态变化等数据表；保留批次时间、来源和数据质量状态。
- 数据隔离：严禁把本机 runtime/SQLite、原始 Excel、客户联系人/电话/地址、Cookie、密码打包或展示给无关用户。页面只返回业务展示所需的最少字段；导入文件需做字段白名单和质量校验。
- 现有本机文件监听器和 `127.0.0.1:4174` API 不能由云端访问。请不要写死 localhost、读取本机路径或假设本机服务已上线。数据接入先提供受权限保护的“上传并校验数据源”流程，采用批次幂等、失败保留上次成功数据；后续再接安全的服务端推送/API，不能依赖本机浏览器或本地 SQLite。
- TMS 状态口径：物流状态“开放”“委托”“确认”视为未提货，其他非空状态视为已提货；缺失状态不推定为已提。含“自提”的记录排除。业务日期按生产日期 + 1 天，并将生产日期当天 00:00–12:00（含 12:00）另计入当天业务日期。
- SP 合单：相同运单 ID/SP 作为一个合单；件数按 SOO 行求和，方数对同一 SP 只计一次。每小时提货效率以同业务日首次检测到状态变为已提的小时记一次，后续小时不重复计入。
- 区域/仓库/承运商/渠道筛选关系、多选/全选/反选/清空行为，以及刷新后恢复筛选条件，按导入页面现有实现保留。
- 页面刷新后应从托管数据库读取最新成功批次；显示源文件名、批次时间、有效记录数、质量检查、同步状态和延迟提示。任何导入失败都保留上次成功数据并明确报错。
- 完成后提供表结构、接口说明、权限配置说明和验证清单；用脱敏测试数据验证指标、筛选、下载、权限与失败回滚，再申请发布。

## 当前环境边界

本机实时数据链路目前是：当日工作流文件夹 → macOS watcher → 本机 SQLite → 仅监听 `127.0.0.1:4174` 的 API → 页面。它不会自动迁移到妙搭。妙搭完成页面/数据库迁移后，还需选定一个云端数据接入方式，并由可安全访问云端的服务把每小时经过校验的数据批次推送进去；不要把本机地址暴露到公网。

## 包内文件

- `index.html`：现有控制塔界面及前端逻辑，作为妙搭迁移参考；其中本机 API 调用需要改造成妙搭服务端数据访问。
- `warehouse-carriers.json`：仓库区域和线路承运商关系配置，不含订单明细。
